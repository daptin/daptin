Root cause and corrections

The NUL corruption came from gopsutil v4.25.1's Darwin native string conversion: it allocated n bytes but advertised n+1 to CoreFoundation. A terminating NUL could overwrite adjacent Go memory. The isolated native canary observed allocated=3, advertised=4, adjacent byte changed to 0x00 on the old version. On the updated version it observed allocated=3, advertised=3 and the adjacent byte remained 0x7f; the undersized conversion safely returned false. Daptin now uses gopsutil v4.26.7 and required transitive updates, including purego v0.10.2. The update includes upstream Darwin library-lifetime and pointer-handling corrections. No schema-copying or toolchain workaround was added.

Olric now rejoins configured seeds through discovery, bounds bootstrap by the supplied context and endpoint, fails metadata reads over to known peers, and closes failed/stale client connections. Initial routing publication uses normal reconciliation; failed publication schedules a coalesced retry at the existing join retry interval. Returned storage values own their bytes, and HKey uses a valid zero-copy string-to-byte conversion. Regression tests cover these paths.

Daptin's production code changes pass the existing startup context to Olric, preserve reference-lookup database errors without nil-handle cleanup panics, and log recovered agent execution panics with backend stack traces. Resource/action/transaction authorities and permission/usergroup caching are preserved. No identity, permission, credential, metering, or routing-policy authority was added.
