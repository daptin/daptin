ONE REQUEST / ONE POLICY CHAIN

Consistency is a runtime property.

Every resource request moves through a shared sequence instead of duplicating rules in each transport or feature.

  1. 01Authenticate

    Resolve the session, user, and groups.

  2. 02Authorize

    Check entity, object, relation, or action access.

  3. 03Validate

    Apply field validation and conformation.

  4. 04Execute

    Read, mutate, aggregate, or run backend outcomes.

  5. 05Meter

    Enforce plan limits and record usage when configured.

  6. 06Publish

    Emit successful data changes to realtime consumers.

DESIGN PRINCIPLES

What Daptin optimizes for.

Own the data

Use standard databases and infrastructure you control.

Compose, don’t stitch

Capabilities meet at shared resource and permission boundaries.

Make behavior discoverable

Expose metadata and OpenAPI rather than hiding runtime contracts.

Enable only what you use

GraphQL, YJS, mail, FTP, and WebDAV-style routes stay config-gated.

Keep product logic server-side

Actions, schedules, credentials, and metering remain behind the API.

Exit cleanly

Readiness, bounded drains, and ordered dependency shutdown protect work in flight.
