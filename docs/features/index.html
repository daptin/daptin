01

FOUNDATION

Data & schema runtime

Describe application resources once and give every other backend surface a durable contract.

Declarative resources

Load YAML or JSON schemas with tables, columns, indexes, relationships, validation rules, defaults, and behavior flags.

Production data shape

Every resource receives stable public references, timestamps, versions, and permission metadata without repeating boilerplate.

Rich field vocabulary

Use types for text, numbers, dates, JSON, location, identity, security, ratings, measurements, files, images, audio, and video.

Database choice

Develop quickly with SQLite, then run against MySQL, MariaDB, or PostgreSQL using the same application model.

Relations and joins

Model belongs-to, has-one, has-many, and many-to-many relationships with generated relationship APIs.

Data lifecycle

Import CSV, XLSX, JSON, or YAML; export structured data; generate test records; enable multilingual fields, auditing, state, or metering.

02

DELIVERY

APIs & discovery

Expose the same resource model through query, mutation, aggregation, and machine-readable discovery surfaces.

JSON:API resources

CRUD and relationship endpoints with filtering, sorting, pagination, includes, sparse fields, and permission-aware responses.

Optional GraphQL

Generate queries, mutations, relationships, aggregations, and action execution from the configured model.

Aggregation API

Group, join, filter, sample, order, and calculate count, sum, average, minimum, maximum, first, or last values.

OpenAPI output

Publish an OpenAPI description of resources, actions, integrations, auth requirements, examples, and data features.

Runtime metadata

Inspect available entities through metadata and generated JavaScript model routes for dynamic tools and clients.

Framework independent

Use plain HTTP from web, mobile, server, automation, or agent clients without adopting a proprietary frontend SDK.

03

GOVERNANCE

Identity & access

Apply the same ownership and group policy to data, relations, actions, topics, and integrations.

Users and groups

Model users, teams, roles, tenant boundaries, memberships, ownership, and default access groups as connected resources.

Granular permissions

Gate read, create, update, delete, refer, execute, and peek operations at entity, row, relation, and action levels.

Authentication flows

Support password signup and signin, JWT sessions, reset flows, and TOTP-based two-factor authentication.

OAuth client

Connect to external OAuth providers, complete browser authorization flows, and store linked tokens securely.

OAuth/OIDC provider

Issue, refresh, revoke, and introspect tokens through authorization, JWKS, userinfo, and discovery endpoints.

Multi-tenant patterns

Combine ownership, usergroups, relations, and row permissions for isolated workspaces without separate application servers.

Understand permissions →
04

BACKEND LOGIC

Actions, schedules & state

Move product logic out of frontend glue and into permission-aware backend operations.

Composable actions

Define inputs, validation, conformations, conditions, ordered outcomes, responses, and instance requirements as data.

Backend outcomes

Perform CRUD, invoke registered Go performers, render content, download files, set headers or cookies, and chain work.

Scheduled tasks

Call the same actions on cron schedules under a selected user identity and permission context.

State tracking

Define allowed source-to-destination events, record transitions, versions, and audit history for resource state.

Data exchange

Map and synchronize resources with external sources or destinations before and after configured operations.

Built-in operations

Handle auth, OAuth, storage, mail, sites, integrations, certificates, publishing, imports, exports, and administration.

Clear scope: state tracking records allowed transitions; it is not a BPM engine with hierarchical states, parallel branches, or implicit entry and exit actions.

05

CONTENT

Files, storage & sites

Keep structured records, binary assets, credentials, and hosted frontends in one governed runtime.

Asset columns

Attach images, video, audio, documents, or other blobs to records with dedicated retrieval and upload routes.

Cloud stores

Connect local or rclone-backed storage providers using encrypted credentials and resource-managed configuration.

Upload workflows

Support direct, multipart, and presigned-style operations where the configured storage provider allows them.

Fast delivery

Serve assets with ETags, cache headers, gzip, in-memory caches, negative caching, and optimized filesystem paths.

Subsites

Route sites by host or path, sync content from storage, apply basic auth, and serve multiple frontends from Daptin.

Go templates

Render resource data into hosted pages with template hooks while retaining the same storage and routing layer.

06

CONNECTIONS

Realtime & protocols

Use the protocol that fits the product without standing up another service for each surface.

Resource events

Publish create, update, and delete events through a bounded worker pool and Olric-backed PubSub.

WebSockets

Subscribe to permission-aware table and topic updates through the structured /live message protocol.

YJS collaboration

Optionally add collaborative document behavior and YJS endpoints to configured resource columns.

Feeds and streams

Expose selected data through stream definitions and RSS, Atom, or JSON-style feed routes.

Mail and files

Enable database-backed SMTP, IMAP, FTP, and FTPS services alongside the HTTP application server.

WebDAV-style routes

Enable CalDAV/CardDAV routes for basic file-oriented storage and discovery where that limited scope is sufficient.

Clear scope: CalDAV/CardDAV support is basic WebDAV-style storage, not a claim of complete calendar or contact protocol compatibility.

07

CONNECTIVITY

Integrations & LLM routing

Turn external APIs and model providers into governed backend capabilities instead of leaking credentials into apps.

OpenAPI imports

Install OpenAPI v2 or v3 operations and expose provider-scoped discovery and execution routes.

Multiple transports

Connect REST, GraphQL, short-lived WebSocket, and unary gRPC operations through one integration model.

Credential boundaries

Resolve OAuth tokens or custom encrypted credentials at runtime without mixing secrets into user input.

OpenAI-compatible API

Serve chat completions, streaming chat, completions, embeddings, models, and tool-call-compatible payloads under /v1.

Provider routing

Map requested model names to configured providers and credentials while keeping clients on one API contract.

Discoverable operations

Publish installed provider operations into Daptin’s OpenAPI output for clients, tools, and agents.

08

PRODUCTION

Metering, caching & operations

Run the application as a product with the controls that are usually postponed until after launch.

Plans and quotas

Define plans, memberships, request and compute limits, pricing metadata, overages, and period quotas.

Usage metering

Record CRUD, action, and LLM usage—including token dimensions—and invoke post-metering credit hooks.

Rate limits

Apply API limits with clustered Olric counters and reject requests before recording usage when hard quotas fail.

Cache and PubSub

Use embedded Olric, LRU/file caches, event queues, and distributed PubSub for coordinated runtime behavior.

Health and visibility

Expose liveness, readiness, statistics, configuration, logs, profiles, metadata, and optional audit records.

Reliable lifecycle

Bind services synchronously, manage TLS, and perform graceful shutdown by draining HTTP and protocol sessions, flushing events, and closing dependencies in order.
